# 树莓派测试清单

在测试 AA 上逐条点一遍，每条做完打勾。适用版本：**1.0.0b1**。

群号、QQ 号都用下面的**测试值**（`100000001`、`10001` 这类），不要用真实号码，也不要把真实号码放进截图或 issue。

---

## 准备

- 按 [GUIDE](GUIDE.md) 第 2 节装好插件，第 4 节分配好权限。
- 两个**普通**测试账号 A、B：都有主角色，状态是 Member。
  **不要用超级管理员测成员功能**：超级管理员不会自动获得入群资格（GUIDE 第 4 节）。
- 一个 QQ 管理员账号（可以是你自己的账号，加进「QQ 管理」组）。
- 「模拟机器人」：树莓派上还没有 Koishi 时，用它代替机器人。
  在 AA 虚拟环境、`myauth` 目录下（GUIDE 第 2 节第 0 步）运行 `python manage.py shell`，
  粘贴 GUIDE 第 2 节第 7 步里的那段代码（从 `import json, secrets` 到 `bot("health")`），按两次回车。之后可以这样调用：

  | 调用 | 作用 |
  |---|---|
  | `bot("groups")` | 机器人看到的群 |
  | `bot("check", {"group_id": "100000001", "qqs": ["10002"], "full_roster": True})` | 假装机器人巡检，上报这个群的**完整**名单（这里只有 `10002`） |
  | `bot("check", {"group_id": "100000001", "qqs": ["10001", "10002"]})` | 查询这几个 QQ 在这个群的判定（不改名单） |
  | `bot("claim", {"qq": "10001", "text": "QQ-XXXXXX", "group_id": "100000001"})` | 假装 QQ 10001 带着验证码申请入群（`XXXXXX` 换成卡片上的验证码） |
  | `bot("events", {"after": 0})` | 机器人拉取事件（事件要等 10 秒以上才能拉到） |

  退出 shell 用 `exit()`；下次再用要重新粘贴。

## A. 安装

- [ ] GUIDE 第 2 节第 7 步的检查全部通过：`check` 没有 `qqbot.` 提示；`curl` 得到 `401`；`bot("health")` 得到 `200` 和 `"config_ok": true`；
      后台「Periodic tasks」里有 `qqbot_reconcile`。
- [ ] `pip show aa-qqbot` 显示 `Version: 1.0.0b1`。

## B. 权限和入口

- [ ] 给 Member 状态挂上「QQ 绑定 - 成员」后，A 在「服务（Services）」页看到「QQ 绑定」卡片，标签是「未启用」。
- [ ] A 的左侧菜单没有「QQ 管理」；A 直接打开 `/qqbot/manage/` 得到 403。
- [ ] 管理员的左侧菜单有「QQ 管理」，卡片底部也有「QQ 管理」按钮。
- [ ] 打开 `/qqbot/` 会自动跳到「服务」页的卡片。

## C. 管理：群和设置

- [ ] 「QQ 管理」→「QQ 群」里添加固定群 `100000001`。
- [ ] 添加身份组小群 `100000003`：不选 AA 组时保存会报错；选一个 A 不在的组后可以保存。
- [ ] 「设置」里把「换绑冷却」改成 `0`（方便下面的测试，测完改回 `24`）。
- [ ] 「操作记录」里能看到上面这些操作。
- [ ] `bot("groups")` 返回这两个群。

## D. 新成员：验证码

- [ ] A 填昵称和 QQ `10001` 并提交：卡片显示验证码、剩余分钟数、3 步说明，以及固定群 `100000001`（看不到身份组小群）。
- [ ] 换一个浏览器登录 A：卡片提示验证码只在原来的浏览器显示；点「重新生成」后得到新码。
- [ ] 用模拟机器人 `claim`，带上卡片上的验证码：返回 `"claimed": true`，`result` 里是 `"decision": "allow"`。
      刷新后 A 的卡片变成「已启用」，显示群名片和群号。
- [ ] 同一个验证码再 `claim` 一次：返回 `"outcome": "code_used"`，`result` 里仍然是 `"decision": "allow"`。

## E. 老成员：免验证与冲突

- [ ] 用模拟机器人 `check`，参数 `"full_roster": True`，名单为 `["10002"]`。
- [ ] B 填 QQ `10002`：马上「已启用」，状态为「老成员免验证」，不出验证码。
- [ ] A 在卡片里「换绑」成 `10002`：A 和 B 的卡片都显示红色「冲突」，不显示群号；
      `check` 这个 QQ 得到 `"decision": "review"`、`"reason": "CONFLICT"`。
- [ ] 管理员在「待处理」里确认 B：B 变为「已验证」，A 的认领作废，操作记录里有记录。

## F. 改昵称、换绑、解绑

- [ ] 改昵称后，卡片上的群名片跟着变；10 秒后 `bot("events", {"after": 0})` 里有这个 QQ 的 `card` 事件。
- [ ] 故意填不合法的昵称（例如超过 12 个字）：提示显示在卡片里，小表单保持展开，填过的内容还在。
- [ ] 解绑时不勾选「我确认要解除绑定」不能提交；勾选后解绑成功。
- [ ] 把「换绑冷却」改回 `24`：换绑时卡片写明「还要等 …」。
- [ ] 管理员在「已绑定成员」→「详情」里强制解绑一个人。

## G. 资格变化

- [ ] 在后台停用 B（去掉 Active）：`check` B 的 QQ 得到 `"decision": "deny"`、`"reason": "USER_INACTIVE"`；10 秒后 events 里有 `recheck`。
- [ ] 把 A 加进身份组小群要求的组：A 的卡片出现这个小群。
- [ ] 在「QQ 群」里停用 `100000001`：`bot("groups")` 里没有它；`check` 这个群得到 `404` 和 `"error": "unknown_group"`。

## H. 手机和深色主题

- [ ] 用手机打开「服务」页，做一次操作：结果提示显示在卡片里、能看到。
- [ ] 切换到深色主题（Darkly）：卡片和管理页的文字都看得清。

## I. 对账

- [ ] `python manage.py qqbot_reconcile` 显示「对账完成」。
